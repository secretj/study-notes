# 쿼리 빌더

- **soft delete 기능**<br>: 기존에 짜여진 코드를 보면 soft delete 기능을 이용하지 않고<br>조건문으로 작성된 부분들이 많은데,<br>사용하면 좋을 것 같다.

```php
class AttachmentDAO extends Model
{
    protected $table = 'attachmentInfo';
		protected $returnType = AttachmentInfo::class;
    protected $primaryKey = 'id';
    protected $useSoftDeletes = 1; // 지정한 컬럼이 1일 때, 삭제된 row로 인식
    protected $deletedField = 'custom_deleted_at'; // 사용할 컬럼의 이름 지정

	public function findAllUsedAttachment(){
			//custom_deleted_at이 1이 아닌 row들만 찾아온다.
			$this->where(['id'=>SERVICEDID])->findAll();
			//custom_deleted_at과 무관하게 전부 찾아온다.
			$this->withDeleted()->findAll();
			//custom_deleted_at이 1인 row들만 찾아온다.
			$this->onlyDeleted()->findAll();
	}
}
```

- **insert()**
  - 첫번째 매개변수
    - 삽입할 연관 배열이기에 테이블의 컬럼과 매칭되는 key를 가진 연관배열을 넣으면 된다.
  - 두번째 매개변수
    - 기본적으로 두번째 매개변수에 값을 할당하지 않으면<br>false로 설정되어 반환값을 TRUE/FALSE로 return한다.
    - 옵션을 할당할 수 있는데, 자동으로 업데이트시간 생성시간 갱신할 지에 대한 여부에 대한 선택 등 <br>그렇게 유용하게 쓰이는 기능은 아니다.
- **update()**
  - 첫번째 매개변수
    - 업데이트할 primary key<br>여러 key를 배열로 지정할 수 있고, 연관배열도 사용이 가능

    > 주의사항 : \$primaryKey를 상단의 field로 정의안하고 업데이트 쿼리빌더를 사용하면 테이블 전체에 업데이트가 됨
  - 두번째 매개변수
    - 바꿀 데이터
  - 매개변수를 사용하지 않는 경우
    - 보통 update에 매개변수를 넣는 방식보다 이 방식을 선호한다.<br>바꿀 행에 대한 조건을 where로 넣고 set에 만든 Entity(혹은 테이블 KEY와 매칭되는 연관배열)를 넣어준다.
- **save()**
  - 매개변수로 전달받은 Entity에 primaryKey와 일치하는 테이블의 row가 존재 여부에 따라 update, insert 를 자동으로 고려해서 사용해주는 메소드<br>즉, upsert 기능을 하는 메소드
- **delete()**
  - \$useSoftDeletes가 설정된 경우 deleted\_at 컬럼을 변경한다.<br>하지만 두번째 매개변수를 true로 설정하면 영구삭제도 가능하다.
- ⭐ **\$validationRules**
  - 우리가 흔히 controller에서 request로 받은 값을<br>validation rule로 검증하고 있는데, <br>이처럼 모델에서도 이 기능을 제공한다.

  ```php
  <?php
  
  namespace App\Models;
  
  use CodeIgniter\Model;
  
  class UserModel extends Model
  {
      protected $validationRules = [
          'username'     => 'required|alpha_numeric_space|min_length[3]',
          'email'        => 'required|valid_email|is_unique[users.email]',
          'password'     => 'required|min_length[8]',
          'pass_confirm' => 'required_with[password]|matches[password]',
      ];
  // validationRules를 통과하지 못했을 때, 메세지
      protected $validationMessages = [
          'email' => [
              'is_unique' => 'Sorry. That email has already been taken. Please choose another.',
          ],
      ];
  }
  ```

  보통 request로 받은 값을 가공하여 Entity로 만들어서 전달하는데<br>가공된 데이터에 대한 검증을 모델에서 하면 편리할 것 같다.<br>이 validationRules은 insert, update, save시에만 동작한다.
