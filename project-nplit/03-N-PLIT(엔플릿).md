> 💡 **Bitcamp**에서 활동하며 진행한 프로젝트입니다. 엔플릿은 사용자 위치를 기반으로 한 **근거리 쉐어링 서비스**입니다. 1인 가구가 증가함에 따라 물건을 소량으로 구매하려는 소비자가 증가했지만 대량 구매의 가격적 이점을 무시할 수 없습니다. 가까운 위치에 거주하는 이웃과 원하는 물건을 공동으로 구매하자는 아이디어에서 시작되었습니다. 함께 구매하고싶은 물건을 본인이 거주하는 곳으로 위치를 지정하면 **쉐어링을 희망하는 참여자들이 모여 물건을 공동으로 구매**할 수 있습니다. 뿐만 아니라 넷플릭스나 왓챠, 쿠팡플레이와 같은 다양한 구독서비스가 증가하고 있습니다. 월마다 구독료를 지불하고 번번히 파티원을 구하는 일에 불편을 느끼는 사용자들은 이 엔플릿이라는 서비스를 이용함으로써 **구독서비스들을 한눈에 관리**할 수 있습니다.

## 📢 주요 기능

- 로그인, 회원가입
- 쉐어링 게시판
- 카테고리별 검색
- 지도구현
- 찜기능
- 채팅서비스 제공

## 💥 내가 담당한 기능

- **<ins>로그인</ins>**
  - 세션과 쿠키를 이용한 로그인 기능
    - 처음에는 spring security를 활용해서 로그인을 구현하려고 했다.<br>하지만 세션과 쿠키의 정확한 정의를 모르는 상태에서 되기만 하는 프로그램을 만드는 건 순서가 맞지 않다. 생각해서 세션과 쿠키를 이용해서 로그인을 만들어보았고, 로그인이 동작하는 원리를 알게 되었다.
  - 쿠키와 인터셉터를 이용한 자동로그인 기능
    - 인터셉터의 prehandle을 오버라이딩해서 컨트롤러를 들어가기 전에 자동로그인 쿠키가 존재하는지 검사하고 존재하면 자동로그인을 시켜주도록 구현을 했는데,<br>인터셉터의 WebMvcConfigurer설정 중 시작부터 컨트롤러의 기능별로 path를 나눠놓지 않아서 excludePathPatterns으로 검증에 제외할 path의 수가 너무 많아져서 왜 계층적으로 path를 설정해야하는지 깨달았다.
  - 이메일을 이용한 비밀번호 찾기
    - EMAIL관련 라이브러리를 추가하여 보낼 계정의 이메일 정보를 세팅하고 회원이 입력한 아이디와 이메일이 일치할 때, 비밀번호를 랜덤 영문 소문자(아스키 코드 97번부터 읽어옴) 12자리로 임시 비밀번호로 변경해준 뒤 사용자 이메일로 발송한다.
      <br>⇒ 여기서 비밀번호 변경이 메일 전송보다 먼저 진행되기 때문에 메일 전송에 실패했을 때는 전송이 안되도록  트랙잭션 처리를 해야함을 배웠다.

- **<ins>회원가입</ins>**
  - JS에 정규식을 활용해서 형식이 맞지않으면 회원가입에 실패하도록 구현해보았다.
  - Required를 input태그안에 넣어서 작성하지 않았을 때, 2차적으로 회원가입에 실패하도록 한번 더 검증했다.

  
- **<ins>개인정보수정/ 비밀번호 변경</ins>**
  - 로그인을 한 상태에서 세션에 담긴 정보를 이용하여 수정하였다.
  - 프로필 변경을 하기위해 단일 파일 업로드를 구현하였다.
    - 절대 경로와 상대 경로를 조합하여 경로를 지정했고, 로컬의 업로드 파일이 저장되는 경로를 그대로 가져와서 사용하면 될 줄 알았다. 하지만 VIEW에서 생각이랑 다른 경로로 가져오길래 fullFilePath라는 컬럼을 하나 추가하여 경로를 맞춰주었다.

  
- **<ins>1:1 문의 게시판</ins>**
  - 문의 등록
    - 등록자는 세션에 저장된 사용자 ID로 설정함
    - 카테고리 선택

      - 문의 등록 자체는 어렵지 않았는데, 드랍다운바에서 선택한 텍스트를 저장할 수 있도록 구현했다.

  - 문의 답변
    - 관리자 페이지에서만 답변을 달 수 있도록 구현했다.
  - 내 문의 내역
    - 세션의 사용자 ID를 파라미터로 문의 내역을 불러왔다.

  
- **<ins>내 프로필 보기/ 다른 사람 프로필 보기</ins>**
  - 내 프로필 정보는 세션 사용자ID에서, 다른사람 프로필 정보는 해당 쉐어링의 작성자ID를 파라미터 값으로 가져왔다.

- **<ins>채팅 기능</ins>**
  - 채팅방 생성  

    - 쉐어링을 생성할 때 자동으로 채팅방 테이블에 생성되도록 구현했다.
  - 채팅방 참가

    - 참가하기를 누르면 해당 채팅방의 번호로 참가목록테이블에 참가한 사람의 세션 사용자 ID를 추가했다.(방장은 쉐어링 생성시 자동으로 참가되도록 했다.)
  - 채팅방 리스트

    - 참가목록테이블에서 해당 ID가 존재하는 채팅방의 번호를 채팅방테이블과 비교하여 채팅방들의 정보를 불러왔다.
  - **메세지주고 받기**

    - 웹소켓과 STOMP.JS를 이용해서 구현했다.
      - 웹소켓과 서버 클라이언트 개념이 없이는 구현이 어려울 것 같아 구현전에 서버/클라이언트, 프로토콜과 웹소켓, STOMP의 원리를 익히고 시작했다.
      - STOMP를 사용하면 채팅방에 메세지를 뿌리는 과정을 내가 구현하지 않아도  subscibe한 상태의 사용자들에게 알맞게 전송해줘서 편리하다는 것을 느꼈다.
  

        **구현 과정** :<br>1. STOMP는 중간 메세지 브로커 역할이기 때문에WebSocketMessageBrokerConfigurer 인터페이스를 구현해야 한다.<br>registerStompEndpoints로 해당 링크로 동작하는 SockJs를 만들어 등록하고 <br>configureMessageBroker에서 publish할 때 사용할 url prefix와 subscire할 때 사용할 url prefix를 설정해주었다.<br><br>2. Client JS에서 SockJS를 1번에서 registry로 등록한 /chat으로 하나 생성하고 연결할때 고유 url로 subscribe하고 요청이 들어오면 함수가 실행되면서 화면에서 변화가 생긴다.<br>전송을 하게되면,

        <br>3.ChatController에서 받아서 해당 방을 subscribe한 클라이언트들에게 모두 메세지를 전송해준다.<br><br>⇒ 채팅의 구조를 완벽하게 이해했다고는 할 수 없지만 적어도 서버와 클라이언트의 개념은 확실히 배울 수 있었고, 전체적인 개발 실력이 오른 후에 다시 여러 대의 서버를 이용하는 채팅 기능을 만들어보고 싶다.
